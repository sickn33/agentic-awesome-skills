# Site craft: November 2026

## Direction

- Product: a browsable library of reusable instructions for coding agents, with reviewable Core artifacts.
- Character: precise, practical, readable.
- Visual context: developer tools and documentation; retain AAS black/cyan, Outfit and official marks.
- Visual focus: the recorded MCP contract review and its actual resulting plan.
- Signature: exact skill IDs and inspectable artifacts, rather than decorative dashboard imagery.

## Changes

The existing site mixed heavy headings, tracked uppercase labels, small metadata and cyan borders on unrelated surfaces. Shared tokens now use neutral surface edges, clearer secondary text, a restrained type hierarchy and consistent corner sizes. Cyan identifies selected states and principal actions. Code and artifact identities retain monospace; interface labels use the text face.

The homepage keeps its existing sections, historical example data, keyboard-operated stages and artifact disclosures. The plan is the focal output; its supporting goal and selected skills have quieter treatment. The example links directly to its recorded project. Setup, video and maintainer sections retain their content with clearer spacing.

Catalog controls take less vertical space. The A–Z directory sits in the shared catalog navigation. At tablet widths, the category rail yields to the existing category selector so result descriptions remain readable. Documentation uses its collapsible navigation earlier for a wider reading column. Skill details use neutral metadata and consistent actions; actual selected/saved states remain distinct. Workbench gives the recorded review a clear action and keeps optional discovery subordinate. The A–Z directory has its own reading layout, and shared selections retain phone-side gutters. Sponsors and information pages inherit the shared visual system without changing their claims or assets.

## Verification scope

Browser review covers desktop, 768px tablet and 390px phone layouts, including homepage, catalog, plugins, Workbench, documentation, skill detail, teams and sponsors. The recorded Workbench example loads valid stack, plan and evidence with matching bindings. Catalog filters, shortlist controls and homepage artifact disclosures must remain operable. Preserve focus indicators and reduced-motion support.

Before integration, run the protected committed-head preflight, full repository checks and web coverage/build. Existing SEO verification must continue to pass: routes, metadata, canonical URLs, rendered content, structured data, sitemap and discovery files retain their contracts. This is a source-only site update, not a catalog release.

## Design references

The polish follows [Unslop](https://heydamir.design/unslop) by Damir Sokolovsky, licensed CC BY 4.0. Its audit and spacing, color, copy, typography and detail passes are adapted to the established AAS identity.

Stageshow's craft guidance informs the hierarchy and framing of the existing interactive product example. This change does not introduce an authored faux-interface scene, a new animation runtime or a fabricated product result; no gold-example rehearsal or film check is claimed. The real artifacts remain in `docs/examples/workflows/mcp-contract/`.
