# Выгрузки и mapping.json

## Пример

`examples/export-example.xlsx`: книга, которую можно отдать оператору как образец или заполнить и загрузить как есть. Листы "Инструкция" и "Колонки" объясняют, что и откуда брать, листы "Депозиты", "Выводы", "Бонусы", "Ставки", "Игроки" показывают данные на 8 вымышленных игроках, по одному на сценарий. Для книги в этом формате готов `examples/mapping-example.json`: скопировать рядом с файлом и поменять `path`.

## Что выгрузить из бэк-офиса

Google Таблицы: Файл, Скачать, Microsoft Excel (.xlsx), все листы попадут в одну книгу. Ссылки на таблицы скилл не открывает: ссылка, доступная без входа, видна любому.

Первый запуск и раз в месяц: период 60-120 дней, чтобы у когорты FTD были 7 дней на второй депозит и 30 дней на Sum Dep. Каждый день: операции за последние 7 дней и список игроков с датой первого депозита (поле `ftd_time`), иначе в короткой выгрузке нельзя отличить FTD от старых игроков. CSV или XLSX, любые названия колонок: скилл сопоставит их сам. Без имен, почты и телефонов: нужен только ID игрока.

| Файл | Обязателен | Колонки | Что дает |
|---|---|---|---|
| Депозиты | да | игрок, дата и время, сумма, статус, способ оплаты; валюта, если их несколько; причина отказа | FTD, второй депозит, Sum Dep, неудачные попытки, способ оплаты, который проходит, отказ по лимиту и блокировка в банке |
| Выводы | желательно | игрок, дата и время запроса, сумма, статус, время выплаты | причины "Вывод отклонен", "Долгий вывод", "Выиграл и вывел", "Отыграл бонус и вывел"; действие по тому, выплачен ли вывод |
| Бонусы | желательно | игрок, дата начисления, название, вейджер, итог (активен, проигран, истек, отыгран) | причина "Бонус с тяжелым вейджером" и действие по статусу бонуса, срез "с бонусом и без" |
| Ставки | желательно | игрок, дата (день или сессия), сумма ставок, сумма выигрышей; раунды, конец сессии | причины "Сгорел быстро", "Выиграл и не вывел", "Деньги на балансе" |
| Игроки | желательно | игрок, дата регистрации, страна, источник, флаги ответственной игры, дата запроса документов | точное определение FTD, срезы по стране и источнику, причина "Запросили документы", исключения |

Депозиты нужны со всеми попытками, включая отклоненные и брошенные: иначе сценарий "Второй депозит не прошел" не посчитается. Депозиты и выводы могут лежать одной таблицей транзакций с колонкой типа операции. Ставки подходят дневные (игрок, день) или по сессиям (игрок, начало сессии, конец сессии).

## mapping.json

Лежит рядом с выгрузками, пути в нем относительные. Поле `path` принимает файл, маску (`deposits_*.csv`) или список файлов: файлы с одинаковыми колонками склеиваются. С `"latest": true` из всех файлов по маске берется один самый свежий по времени изменения: так ежедневные выгрузки копятся в одной папке, а расчет идет по последней.

Готовые варианты: `examples/mapping-example.json` (книга в формате примера), `examples/mapping-csv-example.json` (CSV по запросам `examples/export-queries.sql`, файл на лист, с масками и `latest`), `examples/mapping-one-file-example.json` (минимум одним запросом: депозиты и выводы с данными игрока в каждой строке; один и тот же файл читается как `transactions` и как `players`).

```json
{
  "currency": "EUR",
  "fx": {"USD": 0.92, "CAD": 0.66},
  "files": {
    "deposits": {
      "path": "deposits.csv",
      "dayfirst": true,
      "decimal": ",",
      "columns": {"player_id": "User ID", "time": "Created", "amount": "Amount", "currency": "Currency",
                  "status": "Status", "method": "Payment method", "country": "Country", "is_ftd": "First deposit",
                  "reason": "Decline reason"},
      "status": {"success": ["Approved", "Success"], "declined": ["Declined", "Failed", "Error"],
                 "abandoned": ["Cancelled by user", "Expired"], "pending": ["Pending"]},
      "decline_reasons": {"limit": ["Deposit limit reached"], "block": ["Gambling blocked by issuer"]}
    },
    "withdrawals": {
      "path": "withdrawals.csv",
      "columns": {"player_id": "User ID", "time": "Requested", "amount": "Amount", "status": "Status", "done_time": "Paid at"},
      "status": {"success": ["Paid"], "pending": ["Pending", "In review"], "declined": ["Rejected"], "cancelled": ["Cancelled"]}
    },
    "bonuses": {
      "path": "bonuses.csv",
      "columns": {"player_id": "Player", "time": "Issued", "name": "Bonus", "wager": "Wager", "amount": "Amount", "status": "State"},
      "status": {"active": ["Active"], "lost": ["Lost"], "expired": ["Expired"], "completed": ["Wagered"], "cancelled": ["Cancelled"]},
      "wager_by_name": {"Welcome pack": 40}
    },
    "bets": {
      "path": "daily_activity.xlsx",
      "sheet": "Sheet1",
      "columns": {"player_id": "Player", "time": "Date", "bets": "Bets", "wins": "Wins", "rounds": "Rounds"}
    },
    "players": {
      "path": "players.csv",
      "columns": {"player_id": "ID", "reg_time": "Registered", "country": "Country", "source": "Affiliate", "kyc_time": "KYC requested"},
      "rg_flags": ["Self-excluded", "Deposit limit", "Cooling off"]
    }
  }
}
```

Одна таблица транзакций вместо `deposits` и `withdrawals`:

```json
"transactions": {
  "path": "payments.csv",
  "columns": {"player_id": "Player ID", "time": "Created At", "amount": "Amount", "currency": "Currency",
              "status": "Status", "type": "Type", "method": "Method"},
  "type": {"deposit": ["Deposit"], "withdrawal": ["Withdrawal", "Payout"]},
  "status": {"success": ["Approved", "Paid"], "declined": ["Declined", "Error", "Rejected"],
             "abandoned": ["Cancelled by user"], "pending": ["Pending"]}
}
```

## Поля

- `player_id`, `time`: обязательны во всех файлах.
- `amount`: обязательна в депозитах; в выводах и бонусах желательна. Знак не важен, минус у выводов убирается.
- `status`: каждое значение из выгрузки разнести по `success`, `declined`, `abandoned`, `pending`, `cancelled`. Скрипт остановится, если найдет статус без сопоставления. Если колонки статуса нет, все строки считаются успешными, а неудачные попытки не видны.
  - Депозиты: `success` успешный; `declined` отказ банка или провайдера, ошибка; `abandoned` игрок отменил, бросил оплату или она истекла; `cancelled` тоже неудачная попытка (игрок хотел внести и не смог); `pending` не учитывается.
  - Выводы: `success` выплачен; `pending` в обработке, считается запросом и может стать "долгим выводом"; `declined` отклонен оператором (причина "Вывод отклонен"); `cancelled` и `abandoned` отменен игроком, не считается.
  - Бонусы (необязательно): `active` еще отыгрывается, `lost` проигран, `expired` истек, `completed` отыгран, `cancelled` отменен. Без статуса тяжелый бонус считается законченным.
- `currency` и `fx`: курс это сколько единиц валюты отчета в одной единице валюты строки. Скрипт остановится на валюте без курса.
- `dayfirst`: задается для каждого файла, по умолчанию `true` (05.03.2026 = 5 марта). Для американского 03/05/2026 нужен `false`. `sd_inspect.py` подсказывает порядок, если по данным он однозначен.
- `tz`: пояс времени в файле, если в самих значениях его нет: `"+03:00"`, `"-05:00"`, `"UTC"`. Значения с поясом (`Z`, `+03:00`) приводятся к UTC сами. Если в одних файлах пояс есть, а в других нет, скрипт пишет оговорку `mixed_tz`: спросите пользователя и задайте `tz`.
- `decimal`: `","`, если суммы записаны как `1 234,50`. Без поля формат угадывается по значению.
- `is_ftd`: отметка первого депозита, если она есть в выгрузке. Тогда FTD берется по ней.
- `wager`: число (40, `x40`). Если колонки нет, вейджер берется из `wager_by_name` или из названия бонуса (`Welcome 100% x40`).
- `done_time` у выводов: когда вывод выплачен. Нужен для причины "Долгий вывод" и состояния "выплачен". Без него долгим считается только вывод, который висит в обработке дольше порога.
- `kyc_time` у игроков: когда запросили документы. Без него причина "Запросили документы" не считается.
- `ftd_time` у игроков: дата первого депозита. Нужна для ежедневных коротких выгрузок: FTD считается, только если он случился в пределах выгрузки.
- `bets`, `wins`: суммы ставок и выигрышей реальными деньгами за строку. Вместо `wins` можно `ggr` (ставки минус выигрыши). `end_time` дает длину первой сессии.
- `rg_flags`: колонки флагов. Любое значение, кроме пустого, `0`, `no`, `false`, `нет`, `ні`, считается флагом.
- `reason` у депозитов и `decline_reasons` (необязательно): причина отказа из кассы. В `limit` перечислить значения про лимит депозитов (лимит игрока или законный лимит страны), в `block` значения, где прямо сказано, что гемблинг заблокирован банком или самим игроком. Отказ по лимиту получает действие "объяснить лимит" без другого способа оплаты, игрок с блокировкой исключается, как флаг ответственной игры. Остальные причины ("Insufficient funds", "Do not honor") это обычный отказ. Без колонки законный лимит проверяется по суммам игрока в выгрузке (`references/geo_rules.md`).
- `method_types` (в корне mapping.json, необязательно): тип каждого способа оплаты из выгрузки, например `{"Instant transfer": "instant_bank", "Debit card": "card", "Credit card": "credit_card"}`. Типы: `card`, `credit_card`, `instant_bank`, `online_banking`, `ewallet`, `voucher_cash`, `mobile_money`, `crypto`. Нужен для правил стран: запрещенные в стране типы не подсказываются, а без своей статистики по стране подсказывается основной для нее тип. Без поля тип угадывается по общим словам в названии.
- `--country BR` при запуске: страна игроков, у которых в выгрузке нет страны, для правил стран.
- Лишние колонки (статус бонуса, ID транзакции и другие) не мешают: скрипт читает только сопоставленные. Колонки с именами, email, телефонами и адресами не сопоставляются никогда.

## Проверка готовности

`python3 scripts/sd_analyze.py --mapping mapping.json --out <папка> --check` читает выгрузки по mapping и без расчета печатает: сколько причин из 12 посчитается и что добавить для остальных, режим (полный или список, сколько FTD старше окна), есть ли страна у FTD, флаги ответственной игры и типы способов оплаты для правил стран. Тот же итог есть в `summary.json` (`readiness`) и строкой над таблицей причин в отчете.

## Как определяется FTD

1. Есть `is_ftd` в депозитах: по отметке.
2. Есть `ftd_time` у игроков: FTD это первый успешный депозит, если дата первого депозита попадает в выгрузку.
3. Есть дата регистрации: учитываются игроки, зарегистрированные не раньше первого дня выгрузки, иначе их первый депозит мог быть до начала периода.
4. Нет ничего из этого: первые 30 дней выгрузки служат историей (`--warmup-days`), FTD считаются после них. Выгрузка короче 31 дня без дат останавливает расчет.
