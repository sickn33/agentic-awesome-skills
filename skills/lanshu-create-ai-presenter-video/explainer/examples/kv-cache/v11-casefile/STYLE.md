# V11「案卷」· KV cache 案卷版

同一套案卷 kit（`kits/v11-casefile`），把「为什么大模型越写越慢」当一桩案子来查：立案 → 取证 → 查明 → 修复 → 结案。
一块软木板，五个工位；每进下一个工位，镜头顺着红线滑过去；讲完拉远，整块板连着红线，案卷夹和四张索引卡就是复习图。
故事：`stories/kv-cache-casefile`（61.4 s，已配音）。

| 画面（案卷） | 真名（配音） |
| --- | --- |
| 案卷 07 封面，盖「立案」；「模型：同一个 ✓ 机器：同一台 ✓」 | 异常：同一个模型、同一台机器 |
| 证物 A 生成日志：打字机一行比一行打得慢（12 → 96 ms，标「示意」） | 回答越长，后面每个字出得越慢 |
| 嫌疑名单三条（蓝钉 = 假设），盖「推测」，第三条打红问号；一根蓝线（猜测）从日志牵到它 | 嫌疑：机器旧 / 模型累 / 每一步都在做重复的事 |
| 证物 B 现场照片：七张字块 + 新来的「多」（红圈），蓝色回看箭头指向前面每一个 | 每出一个新 token，都要回看前面所有 token |
| 照片日期戳 STEP 08；前面七块逐个编号；每块下面冒出 K、V 小牌，随即变锈色；笔录「要算 8 份，其中重算 7 份」；红线从「回看前面」连到「又算一遍」 | 第 8 步，前面 7 个 token 的 Key、Value 又被重算一遍 |
| 三张嫌疑卡排成一列：前两张蓝笔划掉、盖「排除」；第三张蓝钉换成红钉，红圈 +「已证实」；证据红线从笔录和「又算一遍」牵过来 | 证据串起来了：不是机器旧，也不是模型累 |
| 证物 D 计算记录：第 1–8 步的三角格，锈色斜线 = 早就算过又算一遍；「8 步一共算了 36 份，其中 28 份早就算过」 | 每一步都在重算早就算过的东西（facts：1+2+…+8 = 36，28 份重算） |
| 证物 C KV 缓存登记卡：token / K · 匹配 / V · 内容，每行 ×1，盖「已存档」 | KV cache：每个 token 的 K、V 只算一次，存进缓存 |
| 新的一行「多 K8 V8」黄色高亮；黄笔顺着 K 列扫一遍、红箭头往上查；笔录「不缓存 8 份 / 有缓存 1 份」；便签「结论：只算新来的那一个，再去缓存里查。」；胶带时间线 T1–T7 走缓存、T8 红色 | 之后只算新来的那一个，再去缓存里查 |
| 结案报告（原因 / 修复 / 代价，盖「结案」）；证物 E 显存账单：一条直线（显存随长度线性增长），2 × 32 层 × 4096 × 2 B ≈ 0.5 MB，× 4096 ≈ 2 GB | 代价：缓存占显存，随长度线性增长；Llama 2 7B 4K 上下文多占 2 GB |
| 拉远到整块板，板上文字隐去，只剩纸、钉和红线；「教训」纸条上逐字打出结尾句，「累」「重复」红圈 | 一句话：慢不是因为累，是因为重复 |

生成日志里的毫秒数是示意（标签上写「示意」）；其余数字都来自旁白或 `story.json → facts`（Llama 2 7B：32 层、4096 维、FP16，每 token 0.5 MiB，4K 上下文 2 GiB，单条请求）。
示例句「因为空气把蓝光散射得更多」是演示用的 8 个 token。字幕的黄色关键片段由 `beats.js` 的 `api.keys` 指定。

声音：`bash tools/sfx.sh`——先 `node lib/kit/events.mjs .` 读出画面自己记录的每个声音提示（拍卡、按钉、打字机、马克笔、盖章、拉线、胶带、镜头移动），
再由 `tools/sfx.py`（`casefile_sfx.bed`）合成底噪；换章时推文件夹、结尾句下一层低音、复习页收尾。

打开这个例子：

```bash
X=<skill>/explainer
cp -R "$X/examples/kv-cache/v11-casefile" ./kv-v11
bash "$X/tools/sync.sh" ./kv-v11 v11-casefile kv-cache-casefile     # 带上已配音的旁白
python3 "$X/tools/stamp.py" ./kv-v11 && python3 "$X/tools/fonts.py" ./kv-v11
(cd ./kv-v11 && bash tools/sfx.sh && npx --yes hyperframes@0.8.81 preview)
```
