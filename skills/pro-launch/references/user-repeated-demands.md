# 他反复强调的事（按重要性排序，来自 288 条自己的消息，括号内为命中条数）

每条：①他怎么说（泛化原话）②为什么重要 ③强制动作（带 ★ 的会被 `scripts/phase_gate.py` 检查）。
开工先读本页，每个阶段结束前对照相关条目。违反任何一条，等于重犯一次已经被骂过的错。

## D1 先学参考：GitHub、获奖作品、App Store、React Bits（49）
①"去看 GitHub 上的开源项目、获奖 App、官方示例工程、React Bits 这类库，把源码和机制学明白，再动手。别用通用模板。"
②没看真参考就写 UI，结果被说"像 web、很土"，是 16 版返工的头号原因。
③★`refs/style-refs/INDEX.md` ≥8 个来源，≥4 个不是 App，≥2 个开源/获奖；顺序是开源库 → 获奖 App → 游戏/海报/艺术 → 灵感平台；每个有"取什么/不取什么"和反推提示词卡。没有 INDEX 不写 UI 代码。
他原话还说：参考的目的是弄明白"为什么它那么精致"，不是抄；只借机制，不借元素。

## D2 沉淀：记住、做成 skill、写进记忆，永远有效（40）
①"能沉淀的都沉淀，永远记住；我随口举的例子只是启发，重点是我没说的。"
②他每次纠正都得重说一遍，最反感。
③★`docs/lessons.md`：本项目新踩的坑 + 已写入哪里（CLAUDE.md / 记忆 / skill）。★根目录 `CLAUDE.md` 含"审美红线"。阶段结束写一条；他的新纠正当场落盘，不等被问。他的例子要扩成整个品类（找他没说的），再收成 2–4 个咬合机制。

## D3 强风格化、不规整、indie、doodle（40）
①"要强风格化、很 indie、手绘拙趣、不规整；不要又土又科技的低端手绘，对标顶尖团队的手绘质感。"
②风格是他判断"这个产品值不值得做"的第一眼；规整圆角矩形=默认=失败。
③★`style-bible.md` 含可检查的"要/不要"和 ≥3 个反例；不规整来自剪纸轮廓、团块、歪放，不是线条抖。搜 `RoundedRectangle/Capsule` 数量降到系统 sheet 之外为 0。颜色别太多太饱和。

## D4 GTM、增长、aha、获客（37）
①"从第一天就按能 go-to-market 来做；要有 aha、有传播点、有人愿意转发；先验证有人付钱再扩张。"
②他的目标是商业化真产品，不是 demo。
③★`feature-map.md` 与 `metrics.md` 都写明 aha 是什么、几步到达；`gtm.md` 一个产品、一个渠道、一个价格、一个周期；做之前先查免费平替，有就不做付费版。

## D5 审美不达标：丑、土、web 感、上个时代（35）
①"图片还是丑，一看就是 AI 做的；不要 web 原型，直接原生；别用二十年前的老组件。"
②他对丑的容忍度为零，自评高分只会被打回。
③★`ui-log.md` 每版有"哪里不如它"并排表 ≥3 行，且不出现 N/10 当结论；直接做 App 不做 web 原型；第 3 版不满意停下写方案。素材丑则成片必丑，换素材不换参数。

## D6 高效、省 token、别卡、别反复验证（27）
①"极致高效；能一键做就一键做；走不通及时回头；首稿通常已经够好，别反复验证；别让我的体验变卡。"
②他的额度有限（Claude 与 Codex 都少），卡顿和重试直接烧钱。
③改前先查已有资产和记忆；调研交给子代理，主会话只收结论；渲染/视频先量原因再动手，不连续重跑；300 回合建议新会话。

## D7 丝滑、转场、动效、一气呵成（22）
①"交互要丝滑顺滑、有新奇但符合直觉的手势；整个产品一气呵成，不是一堆页面。"
②他要商业化，手感是付费理由。
③★`video-brief.md` 写明转场方式（几何/共享元素/手势）；`ui-log.md` 每个新屏写"用到的平台能力 ≥2 项"和"相邻页面如何衔接"；滑动中数字频闪、卡顿算缺陷。

## D8 要深度、详尽、别太简单（20）
①"答案太简单了；我要的是深入的定位报告，不是跟我一问一答。你有深度工作的能力。"
②浅答让他得再追问，浪费他的时间。
③★`positioning.md`、`naming.md` 是完整报告（≥300 字节只是下限）：有对比表、证据、淘汰理由、风险。报告做完当场打开给他看，不只给路径。

## D9 自己做，别问我（20）
①"能做的你自己做，一键执行，不要什么都问我；自己去找，自己搞定。"
②被问小事是他最反感的事。
③只问四类：口味、花钱、对外发布、账号登录付款。其余先查项目文件夹和记忆再自己定，做完告诉他。★`docs/manual-tasks.md` 一次列全需要他本人做的事，之后不逐个打断。

## D10 用好我的工具和 MCP（20）
①"我接了那么多连接器和 MCP，你要主动用，沉淀过的能力别浪费。"
②工具白接，他会觉得你没尽力。
③开工先查 session 里可用的连接器：找参考 → Mobbin/Refero，出稿 → Figma，生图 → Codex/TapNow，动效 → Rive（见 07）。在 `ui-log.md` 或 `asset-list.md` 记一行"用了哪些、没用哪些及原因"。

## D11 好素材，别丑，别重复同一张（18）
①"素材不要丑；示范图不要每个都一样；能用好素材就用，没有宁可留白。"
②③`asset-list.md` 每个素材有来源与授权；同一素材不重复出现；示范照片多样（全身/半身/风景）。美术不靠代码画。

## D12 真实、不造假、要证据（14）
①"要真实可落地的需求，不是想象；失败如实说。"
③★`positioning.md` 数字标【实查】/【判】；权限被拒、离线、没识别出要如实提示。收入没来就说没来。

## D13 用户画像：中日韩越、大学生、出片网红（12）
①"目标用户是爱出片、跟潮流的年轻人，以 App Store 为核心，中日韩越加英语市场。"
③`positioning.md` 写清用户与市场；找参考时覆盖这些地区的 App Store（`appstore_refs.py --country jp/kr/vn`）。

## D14 说人话，去 AI 味（12）
①"文风太像 AI；不要 emoji、不要破折号和冒号腔；有金句、结构靠排版。"
③所有中文文案发出前走 `renhua`；配图走 `post`。

## D15 大道至简、层级清晰、文字少（10）
①"优秀产品层级更多但不显复杂；文字少，不要一字谜语按钮。"
③功能表有"砍掉"清单；每个可点元素问"第一次见的人懂吗"。

## D16 推翻重来，不小修小补（8）
①"整个可以重构，别管之前的设想，对标顶尖重新做。"
③同 D5 第 3 版规则：写诊断和新方案，旧方案不再叠补丁。

## D17 先给方向、选项、预览让我选（8）
①"先给我 prompt/预览/选项，我来选。"
③口味类问题必带可见预览，2–4 个选项加推荐；没有预览先做预览。

## D18 我看不到就等于没做（7）
①"我点不开报告；先让我看一下视频。"
③报告、图、视频完成后直接打开（文件窗格/浏览器预览/Finder 显示），不只给路径。

## D19 别抄、版权（3）
①"不是抄它，是学它为什么好；避免版权风险，因为是真产品。"
③参考图放 `refs/` 不进成品和 git；素材来源授权入 `asset-list.md`；只借机制。
