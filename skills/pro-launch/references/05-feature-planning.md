# 05 功能策划（功能地图、入口层级、优先级、不堆砌）

读完产出：`docs/feature-map.md`。门槛：核心路径 ≤3 步到 aha；每个功能写出"乘法增量"；砍掉清单非空。

## 步骤
1. **核心循环一句话**：打开 → 做出 → 发出去 → 别人点进来。数一次点击数，与最短参考对比（实测一次，别靠推断）。第一版实测：5 次点击+1 次强制等待，比参考多 1–2 步，多出来的是"牌堆选模板"和"保存后再分享"。
2. **aha 在 30 秒内**：引导页第一屏就展示"前→后"，不要先看 3 页介绍；未登录先让用户做出第一张。
3. **功能地图**（表）：功能 / 入口 / 给核心循环的乘法增量（留存？分享？变现？）/ 成本 / 状态（做、不做、砍）。没有乘法增量的不做。
4. **入口层级**：一屏一个主操作；固定入口放最常用动作（如"选照片"），不要要求用户漫游才找到；相机/连图/实况等并列能力放同一个创建菜单、共用一个创作会话。
5. **AARRR 贯穿**：每一环写一个具体机制和健康线（获取/激活/留存/收入/推荐）。推荐环最便宜的是"作品自带配方码/同款链接"，朋友粘贴即可同款。
6. **状态完整表**：每屏的 空/加载/出错/离线/权限被拒/超长内容/大量数据。缺哪格就是 bug 清单。
7. **砍与诚实**：半成品比没有更糟。假社区、假榜单、未实现的优惠承诺一律删；留下的要做完或标成"即将"。
8. **持久化**：用户选的照片、草稿、设置，重启必须还在（第一次审查最严重的问题就是重启丢照片）。

## 优先级公式（写进表里的一列）
`分 = 对核心循环的乘法增量(1–5) × 用户感知(1–5) ÷ 成本(1–5)`；<2 的进砍掉清单。分数只用来排序，不当结论。

## 反模式
- 先做功能后做风格 → 全部返工。功能地图确定后，先定风格圣经再画屏。
- 把用户举的例子当完整需求（见铁律 2）。
- 多个会话同时重写同一件事；同时做的构建 ≤2 个。
- 复用：动手前查"资产清单"（有什么可改）；必须重写要写一句理由（旧的满足不了验收/性能不达标有数据/已被决定作废）。

## 需求卡（见 assets/templates.md）
假设 / 指标 / 复用什么·最小改动 / 验收 / 放弃标准。放弃标准必须是数字或时间。
