# 03 找参考（铁律：先源码，再获奖，再艺术，最后才是竞品）

读完产出：`refs/style-refs/INDEX.md`（用 `scripts/ref_archive.py add`）+ `docs/competitors.md`。门槛：≥8 个来源、≥4 个不是 App、每个写"取什么/不取什么"。

## 顺序（每一步都有用户被"UI 像 web"打回的教训）
1. **GitHub 开源项目与高质量库**——能拆源码的才是真参考，不是看图：
   - 动效/组件灵感库：React Bits、Codrops（每个 demo 带源码）、Shadertoy（shader 可移植到 Metal）、Rive 社区（可 remix 的 .riv）。
   - 平台开源样板：开源 SwiftUI 应用（大图、字少、一屏一个焦点是它们的共性）、Apple 官方示例工程。
   - 搜法：`firecrawl_search` 的 `developer` 类别，或 GitHub 搜 `swiftui animation`/`metal shader` + stars 排序。把"抓到的机制"写进表，不是链接堆。
2. **App Store 获奖 App 与宣传图**：`/usr/bin/python3 scripts/appstore_refs.py "App A" "App B" --country jp`。宣传图看不到流程，只看版式/层级/色彩/文案；流程另找（Mobbin/Refero/VP0/Screenlane，大多要订阅，先确认可用）。
3. **艺术与游戏界面**：游戏 UI 数据库、独立游戏、海报、插画家、印刷工艺（孔版/剪纸/拼贴）。视觉与交互的上限来自这里，成熟 App 只给下限。
4. **灵感平台**：小红书、Pinterest、Behance。用户转发的笔记链接是方向线索；平台难自动抓，必要时让用户截图。
5. **竞品**：只当功能清单（该有哪些功能），**不拿来参考任何视觉与交互写法**，否则会趋同到"规范化 UI"。

## 每个参考落成一张卡（不要重复看图）
`ref_archive.py add img --id 03 --title ... --source ...` 后填四项：为什么好（机制）/ 反推提示词（英文一句，生成器能复现）/ 取用规则（可检验）/ 拒绝规则（什么算抄）。
全部填完后跑 `ref_archive.py commons`：多张提示词里反复出现的词就是这批参考的真共性（例：色块不描边、不规整来自剪纸轮廓而非线条抖动）。

## 反推提示词模板
`<媒介/工艺> + <构图> + <线条> + <颜色规则> + <纹理> + <文字处理> + <禁止项>`，一句英文。

## 用户给的参考怎么用
- 严格区分：**视觉参考**（只学风格）和**功能参考**（只学功能）。用户发的图被当成功能参考，是一次真实的纠正。
- 精准解析每张图的元素、效果、配色，融合成一套方案，不是挑一张抄。
- 研究完先汇报"发现了什么、用不用、为什么"（表格），用户同意后再动手。
- 注意版权：参考图放 `refs/` 并不进 git、不进成品；只借机制，不借元素。
