# 06 UI/UX 构建循环

读完产出：`docs/ui-log.md` 每版一节。门槛：先预览后代码；不写自评分；第 3 版不满意停下重来。

## 每一版的固定流程
1. **读** `CLAUDE.md` 红线 + `refs/style-refs/INDEX.md`。
2. **三选一预览**：出 2–3 个方向的静态预览（HTML/Figma/截图），每个 = 2–3 个具名技巧（来自参考卡）+ 所需素材。给用户选或混合。**没有预览不许写真代码。**
3. **方案一页**（先于代码）：借鉴哪个具体参考 → 这一屏的核心交互机制 → 用哪些平台能力实现 → 砍掉哪些文字。用户同意再写。
4. **写代码**，每版 git commit，截图存 `screenshots/vN/`。
5. **并排对比**：当前截图 + 具体参考作品放一起，写表：`对象 | 哪里不如它`。至少 3 行，必须具体到元素（"参考里每张纸上的画都不同，我们 23 张是同一张照片"）。不写 8/10 这类分数。
6. **跑 `apple-design`**（iOS/macOS）审查：点击区≥44pt、动态字体、减弱动态、对比度。
7. **记账**：`ui-log.md` 写：参考 / 机制 / 能力 / 截图路径 / 不如参考的地方 / 没验证的地方（真机？触感？）。
8. **第 3 版仍被否**：停。写诊断（结构问题还是皮肤问题？）和新方案，用户确认后在新分支重来。

## 诊断三问（用户说"像 web / 又土又丑"时先答这个）
- **结构**：是不是竖着滚的版块+文字解释+按钮驱动？换皮解决不了，要换成手势与动效驱动。
- **表现力**：是不是只有静态 Shape+描边？没用上平台的动效能力。
- **素材**：是不是代码画的丑素材/重复素材？

## SwiftUI 能力清单（"像 SwiftUI 而不像 web"的来源，iOS 17/18+）
- Metal shader：`.layerEffect/.distortionEffect/.colorEffect`（纸纹、孔版颗粒、错位印刷、液态转场）
- `Canvas`+`TimelineView`（12fps 逐帧涂鸦；低帧率手绘与高刷手势分开，不能让拖动也 12fps）
- `matchedGeometryEffect`、`navigationTransition(.zoom)`（元素从一屏飞到下一屏，不硬切）
- `PhaseAnimator/KeyframeAnimator`、`scrollTransition/visualEffect`、`.sensoryFeedback`
- 一个主角贯穿：用户照片从首页→选择→编辑始终是同一个视图，不淡入淡出。

## 交互语言
- 手势优先于按钮；保留用户明确喜欢的手势（如左右滑换色、上下滑调强度）。
- 按下 80–120ms 立即反馈；层级转换 220–320ms；全 App 共用少量曲线；动画可中断，快速连点只执行最新意图；减少动态时改短淡入。
- 控件不抖（line boil 只用在装饰与选中项）；点击区固定。
- 不要为"有新意"加刻意交互（如"往下按才进编辑器"）：新奇但要符合用户对手机的理解。
