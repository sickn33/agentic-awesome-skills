# 例：一个图像创作 App 的首页，从被否到被接受（泛化）

目的：展示 06 的循环在真实返工里长什么样。产品为虚构的"照片玩法 App"，过程取自真实经历。

## 第 1 轮（被否）：换皮
- 做法：保留"标题+一叠照片+黑按钮+一行说明"，把线条换成手抖描边。
- 用户反馈："又土又丑，像 web，不像 SwiftUI。"
- 自评：每项 8 分。**这是错误信号**：没有参考并排。
- 诊断三问：结构（竖滚 hero 区+按钮驱动）→ 是；表现力（静态 Shape+描边）→ 是；素材（同一张照片重复）→ 是。

## 第 2 轮：研究再动手
研究表（节选）：
| 来源 | 抓到的机制 | 用不用 |
|---|---|---|
| 开源动效库 A 的"抖动照片被光标烧出原色" | 静态是单色，被碰到才显影 | 用：首页主节奏 |
| 开源动效库 B 的"无限画布" | 不是信息流而是一张桌面 | 用：首页结构 |
| 游戏界面 C（用画笔给黑白世界上色） | 颜色是你带来的 | 用：显影的叙事 |
| 竞品 App 若干 | 规范化 UI | 只当功能清单 |
**用户没提但关键的发现**：①"安静→显影"是整个 App 的节奏，等于把"颜色只给内容和选中项"变成动态；②印刷"对版"可以当转场，不需要淡入淡出；③一个主角（用户的照片）从首页飞进编辑器，不硬切。

## 第 3 轮：先预览后代码
出 3 个静态预览：A 孔版桌面 / B 剪报拼贴菜单 / C 纸片墙。用户选 A+C 混合。方案一页：参考→机制→SwiftUI 能力（Metal layerEffect 做显影、DragGesture+visualEffect 做纸的物理、Canvas 12fps 做马克笔线）→砍掉所有说明文字。用户同意后写代码。

## 第 4 轮：并排对比（节选，无分数）
| 对象 | 哪里不如它 |
|---|---|
| 纸片墙参考 | 参考里每张纸上的画都不同且手绘；我们每张是同一张照片，纸色只有一种 |
| 孔版人物参考 | 参考是平涂色块+干净黑线；我们的网点更像漫画印刷，暗部颗粒脏 |
| 上一版首页 | 几乎没有字，第一次打开的人未必知道要拖桌面（未真机验证） |
→ 下一版：每张纸不同粉彩色和裁切；黑墨版只取人像轮廓描线；空位用褪色印子+撕剩胶带引导。

## 第 5 轮：被接受后记账
`ui-log.md` 记录截图路径、参考、不如参考的地方、没验证的地方（触感、12fps 线条、真机性能）。红线补充："示范照片要多样""字体不得使用被否的那款"。

## 这个例子要你学到的
先诊断再研究；预览先于代码；对比表取代分数；没验证的写出来；每次纠正变成一条红线。
