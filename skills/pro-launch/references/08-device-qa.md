# 08 真机与 QA

读完产出：`docs/qa-walkthrough.md`。门槛：标明模拟器/真机；失败路径逐一演示；性能有数字。

## 新用户走查（自己玩一遍，不等用户发现）
1. 全新安装（卸载+清数据），不预置照片，走完"打开→做出→保存→分享"，每屏截图。
2. 用**多团队视角**各过一遍：产品（步数、aha）、美术（对照红线）、增长（有没有分享回路）、技术（卡顿、内存）、交互（可打断、触感）、合规（权限文案、订阅页条款）。
3. 输出每屏问题表：现象 / 违反的原则 / 怎么改，按严重度排前 10。第一次走查就抓到：重启丢照片、权限被拒却播成功动画、付费页永远加载、四套视觉并存、点击区 <44pt、说明框挡图。
4. 状态矩阵：空 / 加载 / 出错 / 离线 / 权限被拒 / 超长昵称 / 大量作品 / 低电量 / 切后台恢复。

## 反伪装
- 失败不能带 ✓、成功震动、彩纸。权限被拒 → 警告样式+"去设置开启"按钮+warning 触感。
- 抠图/人脸失败 → 横幅提示+补救，不要静默降级。
- 订阅页要有价格超时(8s)后的"重试"，以及条款与隐私链接（占位链接上架前必须换成真页面）。

## 性能（有数据才算）
- Instruments 记录：首屏、连续换效果、快速调参数、导出；写设备/系统版本/图片尺寸。
- 渲染任务最多"1 个进行中+1 个最新待处理"，过期预览丢弃（丢弃≠取消后台计算，要真取消）。
- 缩略图缓存键含照片 ID/参数/尺寸，设内存预算；只预热当前与相邻项；离屏停止动画。
- 帧预算：60Hz≈16.7ms，120Hz≈8.3ms，是预算不是成绩；**不要用模拟器观感宣称 120fps**。
- 删除"等 0.3 秒再导航"这类时序假设，改成确定的导航状态与完成事件。

## 无障碍
Dynamic Type（设上限并测 XXXL）、减弱动态、`accessibilityLabel`（纯图标按钮）、对比度≥4.5:1（估算要写"估算"）、最小字号 11pt。

## 卡死排查（开发工具本身卡，而不是 App）
先量再动，别先杀进程：
1. 看会话上下文大小与内嵌图片数（一次 95 万 token 且从未压缩，104 张图 31MB，就是慢的根因）；杀进程无用，恢复会重新加载同一份历史。
2. 查网络上行（上传 5MB 测速、到 API 的握手时间、丢包）；上行只有 ~0.7Mbps 时带图的长会话必慢。
3. 对策：`autoCompactWindow`/`/autocompact` 调低到 20–30 万，或在里程碑处写 CLAUDE.md 后新开会话；截图比较完就写成文字结论，别反复塞图。
4. 磁盘/内存吃紧也会卡：先列大目录体积给用户确认再清，不自己删。

## 额度
两边额度都少：Claude 做代码/UI/文案，生图与超大量阅读交给其他工具；机械重复活用较小模型；调研开子代理并行，主会话只收结论。
