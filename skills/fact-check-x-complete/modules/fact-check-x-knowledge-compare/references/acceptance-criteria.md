# 验收标准

- 1.1 可独立执行，也可在统一入口中跳过。
- 所有成功平台的事实主张都进入知识点并集。
- 知识点是原子事实，同一变量的不同答案被对齐为一行。
- `direct` 与 `reference` 的边界由用户问题决定，不由信息篇幅决定。
- 每个平台每个知识点都有显式 `covered` 状态。
- claim 的 `covered`、`claim`、`answerExcerpt`、`faithfulness`、`evidence`
  以及知识点的 `comparison`、`trustedAnchor` 均为必填；字段缺失时在 1.1
  原阶段阻断，不得静默补默认值进入权威核验。
- 1.1 必须独立交付 `synthesisDraft`；它明确标为“未核验”，正文非空且只引用
  当前知识点 ID。缺失、冒充权威结论或引用未知知识点时必须阻断。
- `supported` 或 `contradicted` 必须带已捕获正文中的原文子串。
- 有显式引用标记的主张优先使用对应脚标来源；未带脚标的主张可使用平台标明的全局来源。
- `citationMode=mixed` 时不得因存在脚标而排除 `globalReferenceIndexes`。
- `comparison.status` 只比较主张的事实语义；主张一致时不得因来源忠实性等级不同降为 `partial`。
- 一致性必须区分“一致 / 基本一致 / 部分一致 / 冲突”；不改变结论的轻微差异归为 `mostly_consensus`，改变适用性或风险判断的重要条件差异归为 `partial`。
- 普通平台原始引用以 `url` 为准，`normalizedUrl` 不覆盖它；深知可信搜索同源回填时 `url` 为官网主链接，`platformUrl` / `originalUrl` 保留深知收录页。
- 1.1 不使用可信搜索、网络搜索或外部模型 API。
- 深知晓免查锚点必须同时满足平台身份、可信搜索声明、官方来源、忠实性与原文定位五项校验。
- 中间 HTML 按实际平台数动态展示全部原答案和知识点概览；默认 2 家，`N=1` 使用单平台状态，`N≥2` 增加跨平台对比，不得截断第三家及后续平台，下方可逐点追溯。
- 桌面端平台答案区域按实际 N 等宽对齐；`N=4/5` 可在中等宽度分行，但同一行保持等宽。逐知识点宽表只能在表格容器内横向滚动，页面本身不得横向溢出。
- 1.1 外显统一使用“依据展示 / 溯源方式 / 直接展示 / 间接查找 / 逐段溯源 / 无对应的清单”。
