# 验收标准

- 一个请求文件只含一个知识点。
- 云端用户内容只含总标题、当前知识点和必要的差异主张。
- 一致主张不上传 `differingClaims`。
- 无免查锚点时每个知识点恰好一次可信搜索，不按平台重复搜索。
- 多知识点通过线程池独立并发，结果按请求 ID 回收。
- 深知晓锚点有效时请求数为 0，其他平台共用该官方答案和证据裁决。
- 深知晓与其他平台主张相同且均被锚点支持时均为正确；不同者按锚点判错。
- 官方所附材料忠实，包括显然算术推导，归为直接准确。
- 无局部角标但本次回答参考资料中存在逐主张语义匹配且原文可定位的官方材料，也归为直接准确，并标记为回答级语义匹配。
- 当前主张已有局部角标时，局部来源优先；不得用回答后段或回答级官方来源抬级。
- 非官方所附材料忠实且独立核验通过，归为间接准确。
- 无自己的可靠依据但结果正确，归为结果巧合。
- 权威证据证明错误，归为严重误导。
- 可信搜索成功但官方查无，归为凭空编造；服务错误归为待复核。
- 独立权威报告顶部必须交付 `finalAnswer`，并与全部知识点 ID 完整绑定；随后再展开逐点证据和平台裁决。
- 最终 HTML 使用稳定的章节、指标、逐条判定、补充参考、原答案存证和元信息布局。
- 最终 HTML 按实际平台数动态生成指标卡、平台结论卡和逐条判定列；桌面端 `N≤3` 等宽单行，`N=4/5` 在可用宽度内等宽排列或分行，只有逐条判定等高密度表格可局部横向滚动，页面本身不得横向溢出。
- 技能内没有模型 API 客户端、模型配置或模型密钥。
