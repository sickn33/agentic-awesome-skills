# 验收标准

- 同一个用户问题原样写入 `question`。
- 每个目标平台恰有一条平台结果，平台 ID 唯一。
- 成功结果包含完整非空回答，失败结果包含明确状态与原因。
- 回答必须在内容稳定且页面停止生成后落盘；失败默认自动重采 2 次。
- 自动重采仍失败时生成 `capture-recovery.json`，要求运行载体用 Computer Use 恢复浏览器操作。
- 在线采集由 Playwright 直接启动并控制系统 Chromium 浏览器；Computer Use 只用于自动化失败后的恢复。
- `login` 与 `run` 必须前台直接执行并保留真实退出码；执行工具返回可轮询运行会话时持续轮询，不得用 shell 后台任务或 `tail`/`tee` 管道把采集失败显示为任务成功。
- 未获得可见页面或全平台成功证据前，不得向用户宣称浏览器或采集已经启动。
- 登录、短信验证码、人机验证或 CAPTCHA 出现时，保持 Playwright 命令与页面运行，提示用户本人处理，完成后自动续采。
- 登录准备失败、浏览器意外关闭、人工处理超时或可见页面无法继续时生成 `capture-recovery.json`；有 Computer Use 的运行载体立即恢复，没有则停止在 1.0。
- 当前运行载体没有 Computer Use 能力时必须用中文说明能力缺失并停止在 1.0，不得以其他浏览器手段绕过。
- 任一目标平台失败或恢复状态为 `required` 时，禁止进入知识点对比和后续流程。
- 引用标题、原始 URL、标记和平台内顺序与网页现场一致。
- 页面有显式引用标记时，答案与引用对象中的标记均被保存。
- 页面同时存在逐句脚标和全局来源清单时，二者均被保存并标为 `inline`、`global` 或 `inline_and_global`。
- 页面声明“参考 N 篇资料”时，全局来源捕获数不得少于 N；少于 N 必须失败关闭。
- 豆包来源浮层只有标题但已暴露真实 URL 时，优先用可信搜索 `return_full_content=true` 补全与该标题或 URL 匹配的全文，未配置或未命中时再跟随引用链接或提取 PDF。
- 可信搜索全文补全只能增强当前平台已给出的同一来源，必须保留原 URL 并写明 `contentAcquisition`；不得新增或替换平台引用。
- 深知来源经可信搜索匹配为同一材料后，返回全文或段落直接用于判断，不访问源网址二次抓取正文。
- 可信搜索返回的 `源网址` 直接作为官方来源主链接，深知收录页作为辅助链接；未返回源网址时标为 `trusted_search_no_source_url` 并保留收录页兜底。
- 默认选择 2 个平台，也允许任意 N 个平台（N≥1）；平台 ID 必须唯一，所有选定平台成功后才允许进入 1.1。
- `dknowc-deep-research` 必须先等待普通回答完整生成，再点击“深度研究”并接管新打开的可信溯源报告页；最终深度研究答案和来源完整后才可成功。它与 `dknowc-chat` 独立计入平台集合，但不继承后者的可信锚点免查资格。
- 1.0 报告按实际平台数动态展示；`N≤3` 的平台状态、原答案和来源区域在桌面端使用等宽对齐列，`N=4/5` 保持平台卡片对齐，仅允许原答案或来源矩阵等高密度组件局部横向滚动，页面本身不得横向溢出。
- 来源矩阵的长标题必须自动换行；窄屏使用单列或组件内部滚动，不能把整页撑宽。
- 可见/交互模式由 Playwright 直接管理系统浏览器和持久化配置；命令运行期间保留深知晓、豆包主页面供用户处理，命令结束后关闭浏览器进程但保留登录状态。无头/CI 模式必须关闭且无残留进程，临时来源页始终关闭。
- macOS 可见/交互模式优先使用已安装的 Google Chrome、Microsoft Edge、Brave 或 Chromium；一个都没有时进入 Computer Use 恢复并停止在 1.0，不得反复启动 Chrome for Testing。
- 已绑定 PDF 在可信搜索、直接提取后仍无可核验正文时必须失败关闭，进入 OCR 或 Computer Use 接管；不得以正文不足继续生成幻觉结论。
- 豆包展示层的 `f_link_type`、`flow_extra` 参数不属于来源身份，交付 URL 必须移除；其他业务查询参数保留。
- 页面无显式标记时，不推测逐句引用关系。
- 截图、HTML 或 trace 能证明采集现场；敏感登录数据不进入技能包。
- 任何阶段都不得按标题重新搜索并替换平台原始 URL。
- 技能内没有模型 API 客户端、模型密钥或模型选择配置。
- `validate_results.py` 与冒烟测试通过。
