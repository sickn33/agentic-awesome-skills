# 验收标准

## 架构

- 对外入口是轻量编排 Skill，不复制 1.0、1.1、可信搜索或报告实现。
- 原始答案采集、知识点对比、权威证据核验均可独立安装和独立调用。
- 四个 Skill 全部使用中文说明和中文交互提示。
- 语义分析使用当前承载技能的智能体，代码中没有模型 API 客户端、模型名称、模型密钥或模型路由。

## 1.0

- 完整回答、原始引用列表、引用标记、原始 URL 和现场存证无损保留。
- 原 URL 不被标题搜索或其他 URL 替换。
- 失败状态显式保留。
- 回答停止生成前不得落盘；自动重采仍失败时输出 Computer Use 恢复请求。
- 任一平台失败、回答为空、内容仍是登录/地区提示或恢复状态为 `required` 时，`capture-gate.json` 必须阻止所有下游步骤。

## 1.1

- 形成所有平台知识点并集，区分直接答案与补充参考。
- 精确呈现相同、不同、各自主张、所附依据与来源忠实性。
- 有显式标记只用标记来源；无标记才检查该平台全部原始来源。
- 不调用可信搜索或网络搜索。
- 中间报告按实际平台数动态展示全部原答案与知识点；默认 2 家，`N=1` 展示单平台结构化核验，`N≥2` 增加跨平台对比，不得截断第三家及后续平台。

## 权威核验

- 每个知识点形成一个独立请求，多个请求并发执行。
- 云端用户内容只有总标题、当前知识点和必要的差异主张。
- 主张相同不上传主张；不同才上传差异。
- 深知晓已附官方材料，或其他平台已附 `gov.cn` 材料，且正文实际支持当前主张时免查，实际请求数为 0。
- 非深知晓、非 `gov.cn` 或已有材料不足以裁决的知识点，每点只进行一次可信搜索，所有平台共用证据。
- `dknowExemptCount`、`govExemptCount` 和 `officialExemptCount` 必须与比较结果一致。
- 分类符合直接准确、间接准确、结果巧合、严重误导、凭空编造、证据不足、未覆盖的最终口径。
- 官方前提的一步显然算术推导可判直接准确。

## 最终交付

- 独立交付原始答案、参考文献、引用标记、原始 URL 与现场存证报告，不依赖最终报告的折叠章节才能查看。
- `pipeline.json` 明确登记 `capture/results.json`、`capture/report.html` 和 `capture/report.md`。
- 最终报告使用统一渲染器，保留参考性、逐条判定、补充参考、关键发现、原始存证、指标口径和元信息章节。
- 同一组 JSON 中间产物可离线重现相同类别、指标和报告结构。
- 套件与四个独立 zip 可解压运行，不包含浏览器登录目录、历史运行数据或密钥。
- 四个冒烟测试、技能结构校验、禁止模型 API 扫描和打包清单校验全部通过。
