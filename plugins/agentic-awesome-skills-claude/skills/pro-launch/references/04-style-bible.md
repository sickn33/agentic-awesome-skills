# 04 风格圣经与审美红线

读完产出：`docs/style-bible.md` + 项目 `CLAUDE.md` 的"审美红线"。门槛：每条规则能被一张截图验证；用户确认过一次。

## 结构
1. **一句话风格名**（如"涂鸦志"）+ 一句话理由。
2. **规则表**：每条 = 规则 / 为什么（来自哪张参考卡）/ 怎么检查。
3. **要 / 不要**两栏，不要的必须带用户原话或被打回的版本号。
4. **Token**：纸色、墨色、专色 3–5 个、圆角（可以没有）、字体分工、动效参数（时长/曲线）。视图里禁止写死数值。
5. **反例截图**：被否的 3 个版本截图放 `screenshots/rejected/`，写一行为什么被否。

## 从参考里提炼规则的方法
- 读所有"反推提示词"，圈高频词；高频词就是规则（例："flat/borderless"→ 颜色不描边；"tilted/random sizes"→ 容器规矩、摆放歪）。
- 区分三种"不规整"：线条抖、轮廓不规则、摆放歪。用户要的往往是后两种，只靠线条抖会被骂"又土又丑"。
- 颜色预算：界面框架只用纸色+墨色，彩色只给用户的内容和"当前选中"。
- 字体：为每种语言各定一个标题体/正文体/批注体，用 OFL 授权字体并留许可证；被否过的字体写进"不要"。
- 文字量：能用图/手势/动效表达的就不写说明；一个字当按钮的谜语式 UI 一律不要。

## 常见审美红线（起点，按项目增删）
- 要：整个 UI 一种语言，不是"原生 UI+一点点缀"；示范照片多样（全身/半身/风景）；每屏一个主操作；动画可打断。
- 不要：圆角矩形+胶囊+规规矩矩的框；光滑矢量块加等粗黑描边（像网页 neobrutalism）；高饱和界面；卡哇伊吉祥物；代码画的丑角色；同一素材重复铺满。
- 平台感：iOS 要"像 SwiftUI 而不像 web"。用得上的能力清单见 06。

## 红线的生命周期
用户每次说"丑/土/像 web/不要 X"，当场补一条到 CLAUDE.md 的"不要"，注明版本与原话；每次说"这个好/保留"，补一条"要"。红线只写在项目 CLAUDE.md，一处维护。
