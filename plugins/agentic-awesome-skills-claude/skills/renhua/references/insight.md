# 核心洞察和金句怎么写（从「马当路转正答辩」定稿里拆出来的）

用户评价这份稿子"核心洞察和金句是文案里最重要的，容易理解、逻辑通顺即可"。写任何正文前读这一页，写完按最后的检查走一遍。

## 骨架
1. **主题句**：一句两拍，开头放，结尾原样再放一次。
   例：看准一个方向，就把它做出来；做出来之后，再陪它长大。
2. **一句自我介绍式的钩子**，具体、带一点个人感。
   例：我有无数个好点子，我在学着把它们做出来。
3. **结果先行**：先给最硬的数字，再给一个对照让它有意义。
   例：有效投稿 5.49 万，是立项目标的 2.7 倍。
4. **每段平铺直叙讲事**（做了什么、卡在哪、怎么解），用完整句，不抖机灵。
5. **段尾一句金句**，单独成段，把这一段的道理收住。
6. **核心洞察**放在后半段，是全文最值钱的一段。
7. **坦白和不邀功**：主动说清楚功劳归谁、哪里没做好。
   例：我也想说清楚，增长的底子是小工具本身的产品力，大赛起的是推一把的作用。

## 金句的六种形状（都从这件事里长出来，换个场景就不成立）
- **动作口诀**：先解耦，从重点做起，一层一层解开，越做越顺。
- **画面对照**：多一个合适的人加入，是把蛋糕做大，不是把蛋糕切小。
- **因果原则**：规则要设计得经得起公开，信任才立得住。
- **前后对比**：我以前想做出一个爆款，现在想让一群人都做出好东西。
- **和解句**：我不必变成一板一眼的人，但我需要闭环。
- **短等式**：C 就是 K。
- 还有一种**立场句**：方向看准了，我就不会轻易动摇，除非事实证明我错了。／人不在多，要合适。

## 核心洞察的写法
判断 → 两个数据证明 → 一句短的重新命名 → 所以要怎么做。
例：在小红书，工具本身就是内容。33.9 万篇挂了小工具的笔记里，近九成是别人拿作者的工具发的；话题前 50 的笔记，一半是用户自己整理的合集。用的人也在创作，C 就是 K。所以科技社区运营要服务的，除了少数开发者，还有每一个想拿工具表达自己的普通用户。

## 和 AI 腔金句的区别
- AI 腔：做东西不难，难的是让人看见。（放哪篇都成立，没有数字，没有画面）
- 合格：做东西的成本降到了零，被看见的成本还是原价。（来自这次 291 页 0 访客的事实，有具体对照）

## 写完检查
- 有没有一句主题句，首尾呼应？
- 第一屏能不能看到结果数字和对照？
- 每段是不是一条线讲清楚，读出声不卡？
- 金句是不是从这件事里长出来的？全文金句不超过三句，段尾放。
- 核心洞察有没有数据撑着？
- 有没有夸大、邀功、写了没核实的事？
- 笑点最多一处，没有也可以。
